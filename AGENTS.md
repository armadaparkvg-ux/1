The notes below apply to the **Армада landing** (Next.js) project.

### Service: Армада landing (Next.js)
Standard commands live in `README.md` and `package.json` `scripts`. Node 22 works
(no `.nvmrc`; if the wrong `node`/`npm` is picked up via nvm, both resolve to v22).

- Dev server: `npm run dev` → http://127.0.0.1:3000
- Lint: `npm run lint` (`next lint`) — passes with one pre-existing warning about a
  `beforeInteractive` script in `src/components/yandex-varioqub.tsx`.
- Production build: `npm run build`.
- Static export (for hosting ZIP): `npm run build:static` / `npm run zip:hosting`
  (these set `STATIC_EXPORT=1`, which flips `next.config.mjs` to `output: "export"`).

### Non-obvious gotchas
- **Trailing slashes in dev.** `next.config.mjs` only enables `trailingSlash` when
  `STATIC_EXPORT=1`. In `npm run dev`, requesting e.g. `/courier/` returns a `308`
  redirect to `/courier`. Use the non-trailing-slash path (or follow redirects)
  when hitting routes directly.
- **Dead/unused components.** `TariffQuiz` (`src/components/tariff-quiz.tsx`) and
  `ApplySection` (`src/components/apply-section.tsx`) are defined but not rendered
  by any page. Do not assume a `#quiz` or `#apply` section exists on a live page —
  verify against the actual page component before referencing them.
- **Core interactive flow (no backend).** The site is fully client-side / static;
  there is no form-submit backend. Lead capture works by opening a messenger: the
  "Оставить заявку …" / "Сразу в мессенджер" buttons open an in-app modal
  ("Быстрая заявка") whose message text is generated by `src/lib/apply.ts`
  (`buildApplyMessage`) and then deep-link to Telegram/MAX. A good smoke test is
  `/license` → "Оставить заявку через поддержку" → modal shows the auto-built text.
- External links (Yandex classifier, FGIS check, registration iframes) point to
  third-party URLs and require outbound network to fully load.
